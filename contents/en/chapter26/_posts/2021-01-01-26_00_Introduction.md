# Chapter 26 — Large Language Models

This chapter is the course’s **dedicated LLM hub**. Earlier chapters already built the pieces: attention (Chapter 07), the Transformer block (Chapter 08), static and contextual embeddings (Chapter 18), compression (Chapter 23), and preference-based alignment as an application of RL (Chapters 20–21). What was missing is a single track that treats a **decoder-only language model at scale** as the object of study — how it is pretrained, prompted, aligned, served, and distilled.

Chapter 25 still surveys scaling, multimodality, and open research problems. This chapter is more concrete: it is the self-study path for *using and reasoning about* modern LLMs without re-deriving every Transformer equation. Lesson **26-07** then puts the 2024–2026 decoder block, the interview-style FLOP / memory arithmetic, and a Chinchilla-style scaling sketch in one place.

## Why this chapter exists

An LLM, in the sense used here, is a **causal (decoder-only) Transformer language model** trained to predict the next token on a very large text corpus, then usually adapted so that it follows instructions and stays inside a product’s safety and style constraints.

That sentence hides four design choices you should be able to name:

1. **Decoder-only** — the model conditions on the left context only (causal mask). There is no separate encoder stack as in the original Vaswani encoder–decoder, though encoder–decoder LMs (T5-style) still exist.
2. **Language model** — the training objective is next-token prediction, not a supervised class label.
3. **At scale** — width, depth, data, and compute are large enough that prompting and in-context learning become useful interfaces, not just curiosities.
4. **Adapted after pretraining** — raw next-token models complete text; products need instruction-following and preference alignment.

If you can already walk one encoder layer and one decoder step from Chapter 08, you have the architecture. This chapter answers: *what do we do with that stack when it is the product?*

## Learning goals

By the end of this chapter you should be able to:

- Define an LLM as a scaled causal Transformer LM and contrast it with BERT-style encoders and T5-style encoder–decoders.
- Explain next-token pretraining, subword tokenization, and what a context window actually limits.
- Separate **prompting / in-context learning** from **parameter-updating fine-tuning**, and say when each is the right tool.
- Sketch the alignment pipeline **SFT → preference optimization (RLHF / DPO)** and know where Chapters 20–21 do the RL math.
- Write the softmax + cross-entropy gradient $$\partial\mathcal{L}/\partial z = p - t$$, the stable log-sum-exp, and the CE / KL / entropy relationship used as LM loss.
- Name the serving knobs that matter at decode time (KV-cache, batching, speculative decoding, sampling) and decide **when distillation is the remaining lever**.
- Sketch a modern decoder layer (RMSNorm → attention + RoPE → SwiGLU), give order-of-magnitude FLOPs and inference memory, and state the Chinchilla compute-optimal idea without inventing a fitted curve.
- Distinguish classical KD, synthetic-data distillation, and white-box feature/logit distillation — including the legitimate vs unauthorized-use tension — without treating headlines as evidence.

## Mental model

Think of a deployed LLM as **four stacked adaptations of the same decoder**:

1. **Pretrain** — learn $$p(x_t \mid x_{<t})$$ on broad text.
2. **Adapt the interface** — prompts, few-shot exemplars, and (usually) supervised instruction data.
3. **Adapt the preferences** — human or AI pairwise feedback, not just “next token on the web.”
4. **Adapt the cost** — cache, quantize, batch, or **distill** into a smaller student so the capability is cheaper to serve.

When you can tell which layer a technique lives on, the rest of the chapter is bookkeeping.
